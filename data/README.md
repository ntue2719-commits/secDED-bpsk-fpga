
# SECDED–BPSK Verification Dataset

## 1. Overview

This directory contains deterministic test vectors generated by the
Python Golden Model for the FPGA SECDED–BPSK communication pipeline.

The dataset is used for:
- RTL functional verification.
- Module-level input/output comparison.
- End-to-end pipeline verification.
- LFSR state and error-injection verification.
- BPSK modulation, noise injection, and demodulation verification.

All expected outputs are generated using `python/export_hex.py`.

## 2. Dataset Configuration

| Parameter | Value |
|---|---|
| Input data width | 4 bits |
| Input combinations | 16 (0x0–0xF) |
| Noise levels | 8 (0–7) |
| Error modes tested | 3 (0, 1, 2) |
| Total transactions | 384 |
| SECDED codeword | 8 bits |
| BPSK samples per bit | 8 |
| BPSK samples per transaction | 64 |
| Total BPSK samples | 24,576 |
| Sample width | Signed 8-bit |
| Error LFSR initial seed | 0xA5 |
| Noise LFSR initial seed | 0x01 |
| LFSR reset between transactions | No |

Test matrix:

16 input values × 8 noise levels × 3 error modes = 384 transactions.

Error modes:
- `00`: No error
- `01`: Single-bit error
- `10`: Double-bit error

Reserved mode `11` is supported by the Golden Model but is not
included in this exported test matrix.

All `.hex` files contain one hexadecimal value per line.

Values are stored using two hexadecimal digits per entry.
Signed samples use 8-bit two's-complement representation.

## 4. Input and Output Mapping

The verification pipeline is:

```text
input_data.hex
      |
      v
Hamming Encoder -------> encoded.hex
      |
      v
Bit Flip Channel ------> corrupted.hex
      |
      v
BPSK Modulator --------> bpsk_tx.hex
      |
      v
Noise Injector --------> bpsk_noisy.hex
      |
      v
BPSK Demodulator ------> demodulated.hex
      |
      v
Hamming Decoder -------> decoded.hex
                         status.hex
                         syndrome.hex
                         corrected.hex
```

Additional reference files:
- `config.hex`: transaction configuration.
- `noise_values.hex`: injected noise samples.
- `error_lfsr_*.hex`: error generator state.
- `noise_lfsr_*.hex`: noise generator state.

## 5. Transaction Ordering

Transactions are generated in the following order:

```python
for data in range(16):
    for noise_level in range(8):
        for err_mode in (0, 1, 2):
            generate_transaction()
```

For transaction index `t`:

```text
t = data * 24 + noise_level * 3 + err_mode
```

Examples:

| Index | Input | Noise Level | Error Mode |
|---:|---:|---:|---:|
| 0 | 0x0 | 0 | 0 |
| 1 | 0x0 | 0 | 1 |
| 2 | 0x0 | 0 | 2 |
| 3 | 0x0 | 1 | 0 |
| 23 | 0x0 | 7 | 2 |
| 24 | 0x1 | 0 | 0 |
| 383 | 0xF | 7 | 2 |

Each transaction produces:
- 1 input payload.
- 1 configuration value.
- 1 encoded codeword.
- 1 corrupted codeword.
- 64 BPSK transmit samples.
- 64 noise values.
- 64 noisy BPSK samples.
- 1 demodulated codeword.
- 1 decoded payload.
- 1 decoder status.
- 1 syndrome.
- 1 corrected codeword.

## 6. Sample Index Mapping

Each transaction generates 64 consecutive samples.

For transaction `t`:

```text
start_index = t * 64
end_index   = t * 64 + 63
```

Examples:

| Transaction | Sample Indices |
|---:|---|
| 0 | 0–63 |
| 1 | 64–127 |
| 2 | 128–191 |
| 383 | 24512–24575 |

BPSK bit ordering is MSB-first.

| Codeword Bit | Sample Offset |
|---|---|
| bit 7 | 0–7 |
| bit 6 | 8–15 |
| bit 5 | 16–23 |
| bit 4 | 24–31 |
| bit 3 | 32–39 |
| bit 2 | 40–47 |
| bit 1 | 48–55 |
| bit 0 | 56–63 |

BPSK mapping:

```text
Bit 0 -> +127 -> 0x7F
Bit 1 -> -127 -> 0x81
```

Noise injection uses signed arithmetic followed by saturation
to the range [-128, +127].

## 7. Decoder Status

| Status | Meaning | Expected Behavior |
|---|---|---|
| 0x00 | No error | Return decoded payload |
| 0x01 | Single-bit corrected | Correct error and return payload |
| 0x02 | Double-bit detected | Return diagnostic payload 0x0 |

Status 0x03 is reserved.

The final decoded output is the result of the entire pipeline,
including noise injection and BPSK demodulation.

## 8. RTL Verification Usage

Testbenches can load the reference vectors using `$readmemh`.

Example:

```systemverilog
reg [7:0] encoded_ref [0:383];
reg [7:0] bpsk_ref [0:24575];
reg [3:0] decoded_ref [0:383];
reg [1:0] status_ref [0:383];

initial begin
    $readmemh("data/encoded.hex", encoded_ref);
    $readmemh("data/bpsk_tx.hex", bpsk_ref);
    $readmemh("data/decoded.hex", decoded_ref);
    $readmemh("data/status.hex", status_ref);
end
```

Compare the RTL outputs against the reference data when
their corresponding output-valid signals are asserted.

The testbench must account for module latency, handshake
timing, and transaction boundaries.

A mismatch should report:
- Transaction index.
- Sample index, if applicable.
- Expected value.
- Actual value.
- Error mode and noise level.

## 9. Generate the Dataset

From the repository root:

```bash
python python/test_golden_model.py
python python/export_hex.py
```

Expected output:

```text
PASS: all golden-model tests
PASS: HEX vectors generated
Transactions: 384
BPSK samples: 24576
```

Generated files are stored in `data/`.

## 10. Verification Scope

This dataset supports deterministic functional verification
of the SECDED–BPSK datapath.

It does not directly measure:
- FPGA maximum operating frequency.
- RTL latency in clock cycles.
- FPGA LUT, FF, or BRAM utilization.
- Dynamic power consumption.
- Hardware throughput.

These metrics require RTL simulation, synthesis,
implementation, or FPGA measurements.

Note: The exported matrix uses a continuous LFSR state
across all 384 transactions. Testbenches must reproduce
the same transaction sequence and reset behavior.
